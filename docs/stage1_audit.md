## Ошибки и неопределённости

| ID | Подтверждённая ошибка формата |
| --- | --- |
| q04 | Нет отдельных заголовков «Что проверить», «Что делать» |
| q16 | Нет отдельного заголовка «Что делать» |
| q18 | Нет отдельного заголовка «Что делать» |
| q26 | Нет отдельного заголовка «Что делать» |

У q01 FPR=True, хотя в ответе присутствует посторонняя вставка `iteDatabase`. Это конкретный пример того, что соблюдение структуры не доказывает содержательное качество. Советы ещё не проверены независимым судьёй или по предметным источникам. Причины отсутствия разделов, включая возможное влияние лимита токенов, не установлены: исходные записи не содержат количества сгенерированных токенов и причины остановки.

Метрика v2 считает непустым любой раздел с непустой строкой, даже если это только `-` либо посторонний заголовок. Дополнительные разделы не запрещены и не учитываются как границы обязательных разделов. Это исходная семантика; её исправление задним числом изменило бы baseline. Ограничение сохранено в коде и тестах.

В reference-ноутбуке загрузка модели и токенизатора не закрепляет revision в вызове `from_pretrained`; commit модели записывается уже после загрузки. Новый путь явно использует сохранённую ревизию для обеих загрузок. Историческую ревизию токенизатора из имеющихся артефактов однозначно восстановить нельзя. Результаты нового GPU-пути до фактического запуска не считаются идентичными исходным.

`pip_freeze.txt` отражает большое окружение Colab, включая CUDA-пакеты. Это не проверенный lock-файл для чистой установки. Новый список прямых зависимостей закреплён по сохранённым версиям. Предустановленный torch Colab сохраняется и записывается в новый конфиг. При отличии версий меняется run_id; пригодность этого окружения для T4 ещё требует проверки.

## Реализация и решения

Минимальная архитектура: `metrics.py` — проверка и агрегация; `artifacts.py` — данные, конфигурация, проверки и экспорт; `inference.py` — CUDA-загрузка и генерация; `cli.py` — команды. Модули будущего обучения и судьи не создавались. Конфигурация и вопросы читаются из имеющихся файлов без копирования в новый код.

Старая метрика перенесена с сохранением алгоритма. Тест сравнивает её результаты с функциями, извлечёнными из reference-ноутбука через AST, на всех 30 реальных ответах и дополнительных граничных примерах. GPU-код ноутбука при этом не выполняется.

Новые результаты идут в `outputs/`. Sanity и полный тест разделены каталогами; полный запуск включается явным флагом. Проверка сохранённых ответов обязательна перед продолжением; неполные результаты не получают итоговой таблицы. Защищены исходные каталоги. Дополнительные runtime-данные предотвращают продолжение файла при изменении GPU, CUDA, Python, конфигурации генерации или файла инференса. Клонирование, установка, вызовы CLI и скачивание ZIP находятся в одном новом Colab-ноутбуке без дублирования бизнес-логики.
