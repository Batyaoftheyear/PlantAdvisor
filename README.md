# PlantAdvisor — Рубежный контроль 1

Русскоязычный текстовый консультант по комнатным растениям: уход (`care`) и вероятные причины проблем по симптомам (`diagnosis`). Без изображений. Требования задания — в [PROJECT_SPEC.md](PROJECT_SPEC.md).

[Открыть ноутбук в Google Colab](https://colab.research.google.com/github/Batyaoftheyear/PlantAdvisor/blob/main/notebooks/baseline_colab.ipynb)

## Статус на 05.11.2026

Сохранён один реальный baseline, полученный на Colab T4: `Qwen/Qwen2.5-3B-Instruct`, NF4 4-bit, greedy decoding, 512 новых токенов. `run_id=58f7174a5f13e79c`. Замороженный тест: 30 вопросов, по 15 каждого типа.

| Тип | Прошли форматную проверку | Format Pass Rate |
| --- | ---: | ---: |
| care | 15/15 | 100% |
| diagnosis | 11/15 | 73,33% |
| Всего | 26/30 | 86,67% |

FPR измеряет структуру ответа. Корректность, полезность и безопасность советов этой цифрой не подтверждены. LLM-as-judge, SFT, результаты после обучения и LoRA-веса пока отсутствуют. `judge_prompt_template.txt` — черновой шаблон, без оценок.

Первый инженерный этап выполнен: проверены исходные артефакты, логика baseline вынесена в модули, добавлены CPU-тесты и Colab-ноутбук. **Новый GPU-код и установка зависимостей на T4 пока не проверены.** Аудит и ограничения: [docs/stage1_audit.md](docs/stage1_audit.md). Журнал CPU-проверок: [docs/stage1_validation.txt](docs/stage1_validation.txt).

## Структура

```text
src/plant_advisor/
  metrics.py         # исходная форматная метрика v2 и агрегация
  artifacts.py       # JSONL/CSV, конфигурация, хеши, валидация, экспорт
  inference.py       # загрузка модели, инференс, продолжение прогона на CUDA
  cli.py             # audit / run / export
  __init__.py
  __main__.py
notebooks/
  baseline_colab.ipynb     # рабочий запуск в Colab T4
  reference/
    01_baseline_colab.ipynb # исходный эксперимент
data/eval_questions.jsonl  # замороженный тест, не использовать в SFT
results/baseline/          # неизменённые исходные результаты и окружение
tests/                    # unittest, без GPU и внешних зависимостей
docs/                     # аудит, контрольные суммы и CPU-проверки
outputs/                  # новые прогоны, игнорируется Git
requirements-gpu.txt      # прямые зависимости нового GPU-пути
pyproject.toml            # пакет и CLI
```

Рабочий ноутбук — `notebooks/baseline_colab.ipynb`. Его файл хранится в репозитории, а ячейки выполняются в Google Colab на T4. Локально GPU не требуется: здесь редактируется код и выполняются CPU-проверки. Исходный эксперимент перенесён в `notebooks/reference/`; его код сохранён, пояснения сокращены.

Промпт, ревизия, seed и настройки читаются из `results/baseline/config.json`, вопросы — из JSONL. В рабочем ноутбуке они не дублируются.

## Локальные проверки на CPU

Python 3.10+. Выполняйте команды из корня репозитория. Для аудита и тестов достаточно стандартной библиотеки; устанавливать PyTorch не требуется. Проверено на Windows, Python 3.14.4.

PowerShell:

```powershell
$env:PYTHONPATH = (Join-Path (Get-Location) 'src')
$env:PYTHONIOENCODING = 'utf-8'
python -m plant_advisor audit
python -m unittest discover -s tests -v
python -m compileall -q src tests
python -m plant_advisor --help
```

Linux / Colab, без установки пакета:

```bash
export PYTHONPATH="$PWD/src"
python -m plant_advisor audit
python -m unittest discover -s tests -v
python -m compileall -q src tests
```

Альтернатива для разработки: `python -m pip install -e .`; после установки доступна команда `plant-advisor`. CPU-проверки выполнены через `PYTHONPATH`, установка editable локально не проверялась.

`audit` проверяет JSONL и CSV ответов, уникальность ID, соответствие вопросов, модель и ревизию, хеш вопросов, вычисленный `run_id`, все поля форматной проверки и агрегаты CSV. При несогласованности возвращается ненулевой код выхода. Различия float при агрегации сравниваются с допуском `1e-12`.

## Запуск на Google Colab T4

1. Используйте ветку GitHub с актуальным кодом проекта. Рабочую копию также можно загрузить в Colab вручную.
2. Откройте [notebooks/baseline_colab.ipynb](notebooks/baseline_colab.ipynb) в Colab. Выберите **GPU T4** в настройках среды выполнения.
3. В первой ячейке укажите `REPO_URL` и `REPO_REF` (ветка или тег). По умолчанию это `https://github.com/Batyaoftheyear/PlantAdvisor`, `main`. Клонирование происходит только при отсутствии локальной копии, commit выводится на экран. Существующая копия автоматически не обновляется: проверьте наличие актуальных файлов.
4. Запустите установку из `requirements-gpu.txt` и установку пакета `-e .`. Затем выполните CPU-аудит и тесты. Если Colab запросит перезапуск Python после установки, перезапустите среду и повторите ячейки сверху вниз.
5. Запустите sanity check: по умолчанию `RUN_SANITY=True`. Он генерирует только первые два ответа и сохраняет их отдельно. Проверьте загрузку модели, отсутствие CUDA-ошибок и сами ответы.
6. После успешной проверки измените `RUN_FULL_EVAL=False` на `True` и выполните ячейку полного запуска. Будут обработаны все 30 вопросов; ответы сохраняются после каждого вопроса. Итоговые CSV и график формируются только для полного согласованного прогона.
7. Скачайте ZIP результатов последней ячейкой (`DOWNLOAD_RESULTS=True`). Файлы в `/content` исчезают при сбросе среды Colab.

Открытие ноутбука ничего не запускает. «Выполнить всё» при исходных переключателях запускает установку, CPU-проверки и только два sanity-вопроса; полный тест выключен. Повторная команда продолжает тот же режим только при согласованных конфигурации, runtime и ответах. Частично записанная строка JSONL вызывает ошибку; автоматического удаления повреждённых данных нет.

Те же команды из терминала Colab после установки пакета:

```bash
python -m plant_advisor audit
python -m plant_advisor run
python -m plant_advisor run --full --plot
```

По умолчанию сохраняются:

```text
outputs/sanity/<run_id>/     # 2 ответа, без итоговых метрик теста
outputs/runs/<run_id>/       # полный baseline или его контрольная точка
```

В каждом новом запуске: `config.json`, `source_config.json`, `runtime.json`, `pip_freeze.txt`, копия `eval_questions.jsonl`, `baseline_answers.jsonl`. После полного запуска: `baseline_answers.csv`, `baseline_metrics.csv`, с `--plot` — `baseline_format_rate.png`.

Повторный экспорт таблиц полного нового прогона без GPU:

```bash
python -m plant_advisor export --run-dir outputs/runs/<run_id>
```

Для `export --plot` нужен matplotlib из GPU requirements. CLI запрещает сохранять новые результаты в `results/`, `data/`, `notebooks/` и поверх корня репозитория. Исходный `results/baseline/` читается только для аудита и конфигурации.

## Сопоставимость и ограничения

Новая загрузка явно закрепляет ревизию `aa8e72537993ba99e69dfaafa59ed015b17504d1` для модели и токенизатора. В reference-ноутбуке commit модели фиксировался после загрузки; ревизия токенизатора отдельно не сохранена. Идентичность новых ответов исходным нельзя утверждать до GPU-сравнения.

Прямые ML-зависимости закреплены по исходному конфигу. Matplotlib закреплён по `pip_freeze.txt`; pandas новому коду не нужен. Это **не полный lock-файл** транзитивных зависимостей. Исходное окружение сохранено в `results/baseline/pip_freeze.txt`; устанавливать его вслепую поверх Colab не следует.

Используется предустановленный CUDA-совместимый PyTorch Colab. Его фактическая версия и версии ML-библиотек входят в новую конфигурацию и `run_id`. При отличии версий от исходного baseline CLI сообщает об этом. GPU, CUDA, Python, конфигурация генерации и хеш `inference.py` дополнительно сохраняются в `runtime.json`; при их изменении продолжение существующего файла блокируется. Для нового окружения используйте новый `--output-root`, например `outputs/t4_check_2`.

Сохранены chat template, NF4, float16, seed=42, greedy decoding и `max_new_tokens=512`. Для содержательного сравнения до/после SFT должны совпадать тест, промпт, базовая ревизия, настройки и окружение. Greedy decoding сам по себе не гарантирует побитового совпадения между разными GPU/версиями CUDA. После SFT нужно будет отдельно добавить загрузку адаптера и его идентификатор; сейчас её нет.

## Форматная проверка

Версия: `v2_standalone_ordered_nonempty_sections`.

- `care`: «Условия» → «Рекомендации».
- `diagnosis`: «Возможные причины» → «Что проверить» → «Что делать».
- Заголовки должны быть на отдельных строках, без повторов, в указанном порядке; каждый обязательный раздел должен содержать непустую строку. Разрешена исходная Markdown-разметка и нумерация. Дополнительные разделы допустимы.

Критерий полезен для консультанта: пользователю проще найти условия, проверки и действия. Пример прохождения: `Условия\nСвет.\nРекомендации\nПроверять грунт.`. Пример отказа: `Условия: свет.\nРекомендации: полив.` — заголовки находятся внутри предложений. Другие положительные, отрицательные и граничные примеры — в `tests/test_metrics.py`.

Исходная проверка считает содержимым любую непустую строку, даже отдельный маркер списка. Это известное ограничение v2; оно сохранено и покрыто тестом. Для проверки содержания нужна отдельная оценка.
