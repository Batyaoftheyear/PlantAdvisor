# Правила работы Codex — PlantAdvisor

1. Перед изменениями прочитать `PROJECT_SPEC.md`, `README.md`, `results/baseline/config.json`, test dataset и существующий baseline-ноутбук. Держать все инструкции связанными с фактическими артефактами.
2. Не писать весь рубежный контроль одним заходом. Работать по этапам, объяснять архитектуру и решения на понятном ML-языке; пользователь сам принимает исследовательские решения и анализирует результаты.
3. Не изменять и не перезаписывать `results/baseline/*`, не менять тестовые 30 вопросов, system prompt или метрику без явного согласования. Для новых результатов использовать отдельную папку с новой конфигурацией.
4. В проекте единственный зафиксированный baseline: 512 токенов, run_id `58f7174a5f13e79c`. Не добавлять в репозиторий ранние/несогласованные прогоны.
5. Не допускать data leakage: данные test из `data/eval_questions.jsonl` и близкие перефразирования не должны попадать в SFT train/validation. Соблюдать происхождение и лицензии наборов данных.
6. Не выдумывать результаты обучения, LLM-оценки, работающие CUDA-запуски, веса, логи или ссылку на Hugging Face. Отмечать фактически проверенное/непроверенное.
7. Цель — воспроизводимость на Colab T4: модульный код в `src/`, минимальная последовательная точка входа в `notebooks/`, фиксированные конфиги и версии/инструкции в README; sanity checks и тесты до GPU-прогона.
8. После каждой правки кратко сообщать: какие файлы изменены, зачем, как проверены, что требуется проверить вручную/на Colab.
9. Не устанавливать неизвестные зависимости, не делать пуш/публикацию/создание больших файлов без согласования. Не коммитить секреты, токены доступа, локальные кэши, модели или гигабайтные артефакты.
