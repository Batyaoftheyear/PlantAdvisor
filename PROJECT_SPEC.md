# PlantAdvisor: задание и исследовательский контекст

## Учебная дисциплина
«Генеративные языковые модели», рубежный контроль 1. Тема кейса: «Домашние растения». Цель: разработать и оценить дообучение небольшой instruction LLM под текстового консультанта по комнатным растениям и диагностике проблем по описанию симптомов.

## Пункты задания (все обязательны)

1. Зафиксировать предметную область и постановку задачи.
2. Тестовый прогон базовой модели на 1–2 примерах и сохранение ответов.
3. **Хотя бы одна автоматическая проверка**, обоснование критерия, примеры успеха/отказа.
4. Попытка оценки другой моделью-судьёй (API/веб/локально).
5. Собрать данные для supervised fine-tuning (SFT).
6. Дообучить модель.
7. Оценить до и после SFT хотя бы автоматической метрикой и/или LLM-as-judge; обосновать метрики.
8. Подготовить отчёт и воспроизводимые артефакты: код, веса, данные.

## Что сдать

- Отчёт PDF или Markdown **5–10 страниц**: пошаговое описание удач/неудач, принятых решений; примеры данных и ошибок; количественные и качественные метрики; выводы.
- Код/ноутбуки/скрипты с README, **воспроизводимые на Google Colab T4**.
- Метрики, графики, логи.
- Веса модели или LoRA-адаптера **safetensors либо совместимый формат**, доступные по ссылке.
- Данные для SFT **JSONL либо Parquet**, совместимые с `datasets.load_dataset`.
- LMS: ссылка на репозиторий + отчёт.

## Критерии (максимум 25)

- Описание всех шагов, действий, проблем, решений: **12**.
- Примеры ошибок, ответов и данных: **4**.
- Количественные и качественные метрики, их интерпретация: **7**.
- Выводы: **2**.

## Решения и зафиксированные факты

- Две категории: `care` (обычные рекомендации) и `diagnosis` (вероятные причины, проверки, безопасные действия). Без фото.
- Baseline: `Qwen/Qwen2.5-3B-Instruct`, точная ревизия и конфигурация лежат в `results/baseline/config.json`.
- Системный промпт уже требует разделы `Условия` → `Рекомендации` для `care` и `Возможные причины` → `Что проверить` → `Что делать` для `diagnosis`.
- Форматная проверка **мягкая**: обязательные разделы должны присутствовать, идти по порядку, быть непустыми и не повторяться; дополнительные разделы не запрещены. Не менять её определение задним числом.
- ИТОГОВЫЙ сохраняемый baseline — **только 512 новых токенов**, `run_id=58f7174a5f13e79c`, 30 ответов, Format Pass Rate **26/30 = 86,67%**; 15/15 (`care`) и 11/15 (`diagnosis`). Не импортировать более ранние эксперименты; не упоминать другой baseline как результаты этой версии.
- Качество ответа **не доказано**: есть потенциально неверные советы, побочные текстовые вставки, шаблонность, неуверенная диагностика. Настоящие оценки fact correctness/actionability/diagnosis ещё не получены.
- Предпочтительный метод обучения: SFT через QLoRA на T4. Число примеров 300–500 — предварительная цель, не факт и не требование задания.
- Возможный источник кандидатов: https://huggingface.co/datasets/bmeyer2025/plantclinic-care-corpus . Его **фактическую доступность, схему, содержание, качество, происхождение и лицензию нужно проверить до использования**; не считать автоматически SFT-ready и не загружать без очистки. При необходимости искать альтернативы.
- Обучающие вопросы и их близкие перефразирования не должны пересекаться с тестовой выборкой. Предпочесть отдельные train/validation/test (test уже заморожен); зафиксировать источники и правила фильтрации.
- Для сравнения SFT vs baseline: тот же тест, system prompt, модельная база, генерационные настройки и критерии оценки. По возможности судья оценивает анонимизированные ответы в случайном порядке, с фиксированной рубрикой и несколькими ручными проверками спорных ответов.

## Организационная цель

**Один GitHub-репозиторий, не разрозненные Colab-файлы.** VS Code + Codex для разработки; Google Colab T4 для GPU-задач. Реализация в `src/` (конфиги, проверяемые функции, CLI), а Colab — тонкая точка входа, клонирующая репозиторий и вызывающая компоненты; данные и небольшие результаты версионировать, большие веса хранить отдельно со ссылкой. Не переписывать весь проект автоматически без разбора с пользователем.
